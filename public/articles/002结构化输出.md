# 002｜结构化输出：从 JSON Schema 到可靠结果

> 版本基线：FastAPI 0.141.1、Starlette 1.3.1、Uvicorn 0.52.1、Django 6.0.7、Node.js 24.18.1 LTS。
>
> 核对日期：2026-08-03。文中的源码分析均指向这些固定版本，避免框架升级后实现细节发生漂移。

## 1. LLM 输出：文本、结构化对象与事件流

### 1.1 文本输出

自然语言适合人直接阅读，但不适合作为严格接口。标题、冒号、Markdown 围栏和字段名都可能变化。只要下游需要自动执行动作，就不应依赖正则表达式从自由文本中“猜”结构。

### 1.2 结构化输出的三个等级

| 等级 | 做法 | 保证强度 | 适用场景 |
| --- | --- | --- | --- |
| 提示词约定 | 要求模型“只返回 JSON” | 弱 | 原型、非关键任务 |
| JSON 模式 | 提供方保证输出是合法 JSON | 中 | 字段结构简单，应用仍做校验 |
| Schema 约束 | 按 JSON Schema 或工具参数约束解码 | 强 | 自动化流程、写库、调用外部系统 |

即使使用约束解码，也只能保证**形状**，不能保证**事实正确**。例如 `confidence` 一定是数字，不代表它经过了真实概率校准。

### 1.3 JSON Schema 示例

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "type": "object",
  "additionalProperties": false,
  "required": ["summary", "risk_level", "actions"],
  "properties": {
    "summary": {
      "type": "string",
      "minLength": 1,
      "maxLength": 300
    },
    "risk_level": {
      "type": "string",
      "enum": ["low", "medium", "high"]
    },
    "actions": {
      "type": "array",
      "maxItems": 5,
      "items": {
        "type": "object",
        "additionalProperties": false,
        "required": ["title", "owner", "due_date"],
        "properties": {
          "title": {"type": "string"},
          "owner": {"type": ["string", "null"]},
          "due_date": {
            "type": ["string", "null"],
            "format": "date"
          }
        }
      }
    }
  }
}
```

几个关键设计点：

- `additionalProperties: false` 防止模型悄悄增加调用方不认识的字段。
- 枚举比“风险等级字符串”更稳定。
- 未知值显式使用 `null`，不要让模型编造默认负责人或日期。
- 数量、长度和数值范围尽量在 Schema 中表达。
- Schema 只放必要字段。过度嵌套会增加 token 和失败概率。

### 1.4 服务端仍要二次校验

下面是 Pydantic 校验示例。`call_llm_with_schema` 表示任意支持 Schema 约束的模型调用；不同提供方的参数名并不相同。

```python
from datetime import date
from typing import Literal

from pydantic import BaseModel, ConfigDict, ValidationError


class Action(BaseModel):
    model_config = ConfigDict(extra="forbid")

    title: str
    owner: str | None
    due_date: date | None


class AnalysisResult(BaseModel):
    model_config = ConfigDict(extra="forbid")

    summary: str
    risk_level: Literal["low", "medium", "high"]
    actions: list[Action]


raw_json = call_llm_with_schema(AnalysisResult.model_json_schema())

try:
    result = AnalysisResult.model_validate_json(raw_json)
except ValidationError as error:
    raise ValueError("LLM returned an invalid result") from error
```

校验失败时应采用有限重试：把校验错误和原始结果交给模型修复一次，仍失败就进入降级或人工处理。不要无限重试，也不要把包含敏感数据的完整原始输出直接写进公开日志。

### 1.5 用 LangChain 和 FastAPI 实现结构化输出

LangChain 的 `with_structured_output()` 可以把 Pydantic 模型交给聊天模型。LangChain 会根据模型能力选择合适的调用方式，例如 tool calling 或 JSON Schema，并把模型结果解析成 `AnalysisResult` 实例。应用层不需要自己从 Markdown 围栏中截取 JSON。

下面的例子把同一个 `AnalysisResult` 同时用于两处：

- `structured_llm = llm.with_structured_output(AnalysisResult)`：约束并解析模型输出。
- `response_model=AnalysisResult`：让 FastAPI 在返回客户端前再次校验并生成 OpenAPI Schema。

```python
from datetime import date
from typing import Literal

from fastapi import FastAPI, HTTPException
from langchain_core.prompts import ChatPromptTemplate
from langchain_openai import ChatOpenAI
from pydantic import BaseModel, ConfigDict, Field


class Action(BaseModel):
    model_config = ConfigDict(extra="forbid")

    title: str = Field(description="要执行的行动")
    owner: str | None = Field(description="负责人；无法确认时为 null")
    due_date: date | None = Field(description="截止日期；无法确认时为 null")


class AnalysisResult(BaseModel):
    model_config = ConfigDict(extra="forbid")

    summary: str = Field(min_length=1, max_length=300)
    risk_level: Literal["low", "medium", "high"]
    actions: list[Action] = Field(max_length=5)


class AnalysisRequest(BaseModel):
    text: str = Field(min_length=1, max_length=10_000)


prompt = ChatPromptTemplate.from_messages(
    [
        (
            "system",
            "你是故障分析助手。只根据用户提供的文本判断；无法确认的负责人和日期必须使用 null。",
        ),
        (
            "human",
            "请分析下面的故障记录：\n<source>\n{text}\n</source>",
        ),
    ]
)

llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)
structured_llm = llm.with_structured_output(AnalysisResult)
analysis_chain = prompt | structured_llm

app = FastAPI()


@app.post("/analyze", response_model=AnalysisResult)
async def analyze(request: AnalysisRequest) -> AnalysisResult:
    try:
        result = await analysis_chain.ainvoke({"text": request.text})
    except Exception as error:
        raise HTTPException(
            status_code=502,
            detail="模型结构化输出失败",
        ) from error

    return result
```

安装并启动：

```bash
pip install fastapi uvicorn langchain-core langchain-openai pydantic
export OPENAI_API_KEY="你的 API Key"
uvicorn app:app --reload
```

请求示例：

```bash
curl -X POST http://127.0.0.1:8000/analyze \
  -H 'Content-Type: application/json' \
  -d '{"text":"支付服务出现超时，要求张三在 2026-08-18 前完成修复。"}'
```

可能得到：

```json
{
  "summary": "支付服务出现超时故障",
  "risk_level": "high",
  "actions": [
    {"title": "修复支付超时", "owner": "张三", "due_date": "2026-08-18"}
  ]
}
```

这是普通的非流式接口。在模型调用完成前，FastAPI 还没有发送响应正文，因此结构化解析失败时可以返回 `502 Bad Gateway`。如果改成流式接口，一旦响应头已经发送，就不能再把状态码改成 502，只能通过 `error` 事件表达失败。

这里有三层边界需要区分：

1. **提示词**说明任务和未知值策略，但不能单独保证格式。
2. **LangChain `with_structured_output()`**负责把 Schema 传给模型，并将结果解析为 Pydantic 对象。底层可能使用 provider 的原生 JSON Schema、JSON 模式或 tool calling，具体取决于模型和 LangChain 版本。
3. **FastAPI `response_model`**负责接口层的最后一次校验、序列化和 OpenAPI 文档生成。它不能证明模型说的事实正确，只能保证返回对象符合定义。

如果需要排查模型原始响应，可以临时使用 `include_raw=True`：

```python
structured_llm = llm.with_structured_output(
    AnalysisResult,
    include_raw=True,
)
```

此时返回值会包含 `raw`、`parsed` 和 `parsing_error` 等字段。调试日志应过滤敏感信息，生产接口仍应只返回经过校验的 `parsed` 结果。并不是所有模型都支持相同的结构化方法；当 provider 不支持原生 JSON Schema 时，LangChain 可能退回 tool calling 或 JSON 模式，因此上线前应使用目标模型做一次真实调用测试。

### 1.6 结构化输出与流式输出的组合

一个完整 JSON 对象在最后一个字节到达前通常不能可靠解析。直接把 `{"summary":"...` 这样的半截 JSON 交给 `JSON.parse` 会失败。

更稳妥的选择是：

- **文本逐字展示**：使用 SSE `delta` 事件，完成后再发送 `done`。
- **对象逐条产生**：使用 NDJSON，每行是一个独立、完整、可校验的 JSON 对象。
- **复杂对象渐进生成**：传输 JSON Patch 或语义事件，而不是传输任意 JSON 字符片段。
- **最终结果要求强一致**：流中显示预览，结束后再返回或查询完整的 Schema 校验结果。

推荐的 SSE 事件契约：

```text
event: meta
data: {"request_id":"req_123","model":"example-model"}

event: delta
data: {"index":0,"text":"你"}

event: done
data: {"finish_reason":"stop","usage":{"output_tokens":128}}

```

失败时发送 `error` 事件，客户端按事件名而不是按文本内容判断状态。
